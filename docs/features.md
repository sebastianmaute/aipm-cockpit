# Features

Every feature AI PM Cockpit ships, one row each: a one-line summary to skim, with the full description folded away behind **Details**.

This is the user-facing list. The AI assistant reads a different file — `lib/app-feature-guide.md`, a per-view guide compiled into `src/app/operating-guide-builtin.generated.ts`. The two serve different audiences and neither is generated from the other, so a feature added to one does not reach the other. Update both.

| Action Center | Ranked next-best-actions derived from live project data, each with an executable CTA.<br><details><summary>Details</summary>The engine turns due tasks, at-risk RAID, milestone drift, schedule/budget slippage, stakeholder-comms signals, and tasks that need attention (unassigned, gone stale, blocked, or waiting on an unfinished predecessor) into a ranked queue. The single most-urgent action is promoted to a focus **"Do this first"** card above the Now / Soon / Monitor tiers. Multiple signals on the same item collapse into one row — the most-urgent one, with the rest available under "+N more reasons" — and each tier shows its top few with a show-more control. | Activity log | A chronological record of the project's own history — task / RAID / change / document / absence / shift CRUD with per-field change diffs, an actor on every entry, and text / wildcard / regex search.<br><details><summary>Details</summary>The log belongs to the **project, not the browser**: it is saved on every storage backend and travels with the project, so anyone who opens it sees the same history. Edits record the specific fields that changed (before → after). Every entry names who made the change: you (the name set in Settings), the assistant, or an integration such as a Jira or Outlook sync.
