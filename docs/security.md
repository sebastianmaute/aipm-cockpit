# Security

What the app stores, where it stores it, what leaves the browser, and the
build-time environment variables that change any of that.

This file owns the subject. `README.md` links here rather than summarising it.

## Environment variables

No environment variables are **required** — all integrations work via in-app Settings. These optional build-time variables pre-configure integrations:

| Variable | Purpose |
|----------|---------|
| `NEXT_PUBLIC_MSAL_CLIENT_ID` | Microsoft Entra app client ID (overrides Settings → Integrations input) |
| `NEXT_PUBLIC_MSAL_TENANT_ID` | Microsoft Entra tenant ID (overrides Settings → Integrations input) |
| `NEXT_PUBLIC_TURSO_DATABASE_URL` | Turso database URL (overrides Settings → Integrations input) |
| `NEXT_PUBLIC_TURSO_AUTH_TOKEN` | Turso auth token (overrides Settings → Integrations input); **recommend a scoped token** |
| `NEXT_PUBLIC_AI_POLICY_ORG` | Organisation named as the AI-usage policy owner on the AI consent screen in Settings → AI (overrides Settings → AI Assistant input). Optional: a policy link alone (`NEXT_PUBLIC_AI_POLICY_URL` or the Settings link) is enough for the consent screen to show a policy step, and with no owner name the wording stays neutral. There is no built-in default |
| `NEXT_PUBLIC_AI_POLICY_URL` | Link to that AI-usage policy (overrides Settings → AI Assistant input). Must be `https://`; any other value is ignored and Settings says so. This variable alone gives the consent screen a policy step; add `NEXT_PUBLIC_AI_POLICY_ORG` to name the owner. These build variables are the only way a deployment gets a policy step without a user configuring one in Settings |
| `NEXT_PUBLIC_EXPORT_FOOTER` | Footer line printed on HTML, print/PDF and PowerPoint exports, and the PowerPoint theme name (overrides Settings → Appearance input). A blank value is ignored. With neither this nor Settings set, exports carry the neutral built-in "AI PM Cockpit" |
| `NEXT_PUBLIC_TIMELOG_TENANT` | Timelog tenant slug used whenever the Settings → Integrations tenant field is blank (fills the empty built-in default). Like every `NEXT_PUBLIC_*` variable, it is inlined into the bundle at build time, so a changed value takes effect on the next build, not by re-configuring already-deployed devices. Within one build it is resolved at read time by every reader that calls Timelog rather than frozen once on first load, so any device that never configured a tenant picks it up too, not only a fresh install. Unlike the two variables above, this does **not** override an already-stored, non-blank tenant — the tenant is a URL path segment already sent to the Timelog API and persisted on the device, so a later change here never silently repoints an already-configured install |

Three settings are read by the server at **run time** instead (§762), so they need no rebuild and one build serves every deployment:

| Variable | Purpose |
|----------|---------|
| `AIPM_DISABLED_INTEGRATIONS` | Comma-separated list of server-side integrations this deployment switches off, from `jira`, `confluence`, `timelog`, `ecb` (exchange rates), `stt` (cloud speech-to-text) and `ai` (the AI assistant); unknown names are ignored. A switched-off integration's API route (`/api/jira/*`, `/api/confluence/*`, `/api/timelog`, `/api/ecb`, `/api/stt`, `/api/ai/messages`, `/api/ai/models`) answers `503 {"error":"integration-disabled"}` before it calls anything, and the app hides its controls: the Jira and TimeLog settings, the TimeLog module, the Confluence import, the exchange-rate refresh, the cloud speech engine. `ai` switches every AI feature off: Settings → AI says the organisation switched AI off, nothing is sent, `api.anthropic.com` leaves the CSP `connect-src`, and dictation to a speech service stops too (`/api/stt` refuses). Dictation with the browser's own speech recognition is not affected: it stays available and, in some browsers (for example Chrome and Edge), sends the audio to the browser maker's service. No deployment setting switches it off. Users' stored settings are kept, so removing a name brings an integration back as it was. Unset: nothing is switched off. Changing it needs a server restart only |
| `AIPM_AI_GATEWAY_URL` | Sends AI requests through this app's server and the organisation's AI gateway instead of directly from the browser to `api.anthropic.com` (see [AI features](#ai-features)). The base URL of the gateway's Anthropic endpoint, for Cloudflare AI Gateway `https://gateway.ai.cloudflare.com/v1/<account_id>/<gateway_id>/anthropic`; the server appends `/v1/messages` and `/v1/models`. It must be `https`, with no user name or password, no `@`, whitespace, query or fragment, and must not end in `/v1`, `/v1/messages` or `/v1/models` (any case); a trailing slash is ignored. An invalid value switches AI off for the deployment rather than falling back to a direct call; the reason code (`url`, `token` or `token-without-url`, never the value) is logged on the server once per process as `ai gateway setting invalid: <reason>` and in the browser once per page load as the diagnostic `ai.gateway.invalid`. Unset: the browser calls Anthropic directly, as before. Changing it needs a server restart only. Setting it where it was unset, or unsetting it, asks every user to accept the AI data disclosure again (and to tick background AI again); changing it from one gateway URL to another asks nothing. If the new gateway belongs to a different provider or account, or logs differently, tell users yourself; the app does not ask them again. |
| `AIPM_AI_GATEWAY_TOKEN` | Optional. The gateway's authentication token, sent upstream as `cf-aig-authorization: Bearer <token>` on every relayed call. Server-only: it never reaches a browser, a page or a log. Leading and trailing whitespace is ignored; the rest must be visible ASCII characters only (no spaces, tabs, line breaks or non-ASCII letters), which is what the header can carry. Set without `AIPM_AI_GATEWAY_URL`, or containing any other character, it is invalid and switches AI off, exactly like an invalid URL |

> ⚠️ **Security:** When entered in Settings, the Anthropic API key and Turso auth token are **encrypted at rest** (AES-256-GCM; see [Security Model](#security-model)). A Turso token supplied via `NEXT_PUBLIC_TURSO_AUTH_TOKEN` is different — `NEXT_PUBLIC_*` env vars are **inlined into the build at compile time and are not secret**, so prefer a database/operation-scoped token there and rotate it if it may have been exposed. The Jira and Timelog API tokens and the dictation (STT) API key are likewise **encrypted at rest**; their identifying fields (Jira site URL & email; Timelog host, tenant & email) are stored in `localStorage` unencrypted (identifying, not secret).

## Security model

This is a **local-first, bring-your-own-key** application. There is no application server holding accounts or secrets: you supply your own credentials in Settings, and they stay in your browser (on a gateway deployment the Anthropic key and every AI request also pass through this app's server in transit, without being stored). The one exception is an optional deployment setting, the AI gateway token (`AIPM_AI_GATEWAY_TOKEN`), which only the server reads. That makes the browser profile the security boundary — the trade-off is deliberate.

### What is stored where

| Data | Location |
|------|----------|
| **Anthropic API key, Turso auth token, Jira & Timelog API tokens, dictation (STT) API key** | **Encrypted at rest** — AES-256-GCM ciphertext in `localStorage["aipm-cockpit:secrets"]`; these fields are blanked from the settings blob before it is written. The wrapping key is a non-extractable WebCrypto **device key** in IndexedDB by default. The Anthropic key and Turso token additionally support a **per-secret passphrase** (PBKDF2, 600k iterations) that keeps the value sealed until you unlock it; the Jira and Timelog tokens are device-wrapped only |
| Jira site URL + email, Turso database URL, all other settings | `localStorage["aipm-cockpit:settings"]`, **unencrypted** (the Jira site URL and email are identifying, not secret) |
| AI consent records (interactive and background) | In the settings blob above, with the date, the disclosure version and the AI route (`direct` or `gateway`) each was given under; device settings, not personal data |
| Device key (wraps the secrets above) | IndexedDB DB `aipm-cockpit-secrets`, non-extractable |
| Workspace data (tasks, RAID, changes, milestones, stakeholders, …) | `IndexedDB` on the default Browser backend, or whichever storage backend you configure |

If WebCrypto / IndexedDB is unavailable the app degrades to holding the secrets in memory rather than crashing. Credentials are deliberately excluded from workspace exports (JSON/CSV/Markdown), the activity log, and console output; the secrets ciphertext is likewise excluded from exports and never written to Turso.

### What leaves the browser

- **AI features** — see [AI features](#ai-features) below: every path, its consent level and what it sends.
- **Jira** — credentials and issue data go to the same-origin `/api/jira/*` proxy, which forwards them only to `*.atlassian.net` (SSRF allowlist) and persists nothing server-side.
- **Turso** — workspace data and the auth token go to your own Turso/libSQL database over HTTPS.
- **Microsoft 365** — Graph calls authenticate with MSAL-issued tokens; the app never handles your Microsoft password.
- **Confluence** — page imports go through the same-origin `/api/confluence/page` proxy, which reuses the Jira proxy helpers (the same `*.atlassian.net` allowlist and your Atlassian credentials).
- **Timelog** — credentials and booking queries go to the same-origin `/api/timelog` proxy, which forwards them only to your `*.timelog.com` host. See [integrations.md](integrations.md#timelog).
- **Dictation (STT)** — only while AI is switched on and the AI data disclosure is accepted on this device (otherwise dictation with the speech-to-text service is unavailable; it is never switched to the browser's built-in dictation on its own): recorded audio and the STT API key go to the same-origin `/api/stt` proxy, which forwards them to the OpenAI-compatible endpoint you configure. There is no fixed vendor host to allowlist, so the proxy requires `https`, blocks private and loopback addresses, and refuses redirects.
- **ECB exchange rates** — the same-origin `/api/ecb` route fetches the European Central Bank's daily reference-rate file; no credential or user input is sent.

#### AI features

Every path that sends data to an AI or speech service is one row of the table `AI_DATA_PATHS` in `src/app/ai-disclosure.ts`; the consent dialog in Settings → AI shows the same rows, and `ai-disclosure.test.ts` fails when a row is missing here. Where AI requests go depends on the deployment. By default they go directly from the browser to `api.anthropic.com` with your API key; there is no proxy in between. On a deployment that sets `AIPM_AI_GATEWAY_URL` they go from the browser to this app's own `/api/ai/*` routes, which relay them through the organisation's AI gateway to Anthropic: the same request with your own API key, which the server passes on and does not store or log. The consent dialog, the key note in Settings → AI and Help say which of the two this deployment uses, and a consent records it, so a deployment that changes route asks every user again. Dictation is the exception: it goes to the speech service you configure (see **Dictation (STT)** above). An AI path runs only while AI is switched on and its consent level is accepted on this device; dictation needs the AI switch on and the interactive consent accepted, but no Anthropic key.

Interactive (the AI switch in Settings → AI; each path sends only when you use it):

- **AI Assistant chat** — Your messages; the files and e-mails you attach (an e-mail with its body and its sender and recipient names and addresses); your operating guides; and the project data the assistant reads to answer: tasks with their descriptions and note logs, milestones, RAID items, changes, stakeholders, people in the resource directory, absences (only as “absent”, with the person and the dates), budget figures, calendar events, documents and project details, and, when it searches them, the activity history and your other chats in this project. With every message it also gets the number of your other chats in this project and the titles and last-activity times of up to three of the most recent ones (an unnamed chat is titled with the start of its first message; chats are kept only with a Turso database), and the project’s open insights: up to ten current ones and up to five you acted on with their measured result, one line each. An insight from Timelog names one person (or their Timelog user number when no one in the resource directory is linked) with their logged working time: on how many days a single entry or a day’s total went over a limit, they logged more than their defined hours, they logged time on a non-working day or on a day they were absent (vacation, sick or training), or time in a closed month was changed, with the worst hours, the limit where there is one, and for a closed month the net change. People’s names are included. List results carry no e-mail addresses: the assistant reads one address at a time, only when it needs it, though addresses can still appear in attachments, documents and logged edits. The whole conversation is sent again with every new message.
- **Inline AI edit on a row** — Your instruction, the one row you edit and a short project context (today’s date, task count, groups and labels, and the same open-insight lines the chat gets, so a Timelog insight can name a person with their logged working time), plus your operating guide for inline edits if you have one. The row includes names, dates and descriptions, and for a task its blocker log with the name of whoever logged each entry; for a person in the resource directory their name, job title, department, company, role, whether they are external, whether they are active, and their planned workload per period and whether it is planned in percent or hours. Never sent: e-mail addresses, note logs, a person’s phone number, location, birthday, notes and absence hours, a stakeholder’s notes, influence and interest, and an absence’s type and note.
- **Steering committee report draft** — The meeting agenda you typed, your operating guide for this report if you have one, and a status summary: overall status (RAG), task counts, overdue and due-soon counts, RAID and change counts, up to five change titles, and the names and dates of overdue, at-risk and due-soon milestones. No people’s names or e-mail addresses, unless they are in a title or the agenda.
- **Digest summary, on request** — Overall status (RAG), the number of overdue tasks, the numbers of open and high-severity RAID items, and the names and dates of milestones due soon, plus your operating guide for the digest if you have one. No people’s names, notes or e-mail addresses, unless they are in a milestone name.
- **Forecast import from a spreadsheet** — The sheet you choose, with its name (for a CSV file, the file name without its extension), as a table of its non-empty cells (a sheet too large for one request is not sent), plus your operating guide for the import if you have one. Whatever the sheet holds is sent: usually people’s names and planned hours, and their e-mail addresses and hourly rates when the sheet has them. No other project data.
- **Insight recommendation, on request** — The project name, today’s date, the insight’s type, severity and figures, the titles of up to 30 tasks, the names of up to 30 people (active resources and assignees of open tasks), and the item the insight is about: a milestone with its description, a RAID item with its owner and mitigation, or a person’s job title, department and company. For a working-time insight from Timelog the figures are about one person: their name and Timelog user number, on how many days a single entry or a day’s total went over a limit, they logged more than their defined hours, they logged time on a non-working day or on a day they were absent (vacation, sick or training), or time in a closed month was changed, with the worst hours, the limit where there is one and, for a closed month, the net change, and the first and last dates concerned. Also your operating guide for recommendations if you have one. No e-mail addresses and no resource notes.
- **Analyze next actions with AI** — The project name, today’s date, planned, actual and forecast budget, the next-actions queue (titles and reasons), open tasks (title, status, priority, assignee, due date), active RAID items (category, severity, status, owner, target date), milestones, pending changes, and stakeholder names with their title or organisation, plus your operating guide for analyses if you have one. No descriptions, notes or e-mail addresses.
- **Allocation plan proposal** — Your request, your operating guide if you have one, the plan window and periods, and for each person in the resource directory: their name (or their number in the resource directory if no name is set), role, whether they are external, and their planned and available hours per period. Absences are used to work out available hours and are not sent.
- **RACI suggestion** — Stakeholder names, titles, organisations, categories, influence and interest; milestone names, dates and descriptions; the existing RACI assignments; and your operating guide if you have one. No e-mail addresses.
- **Duplicate task check** — For each task: its number, status, due date, title, assignee and the first 200 characters of its description, plus your operating guide if you have one. No e-mail addresses or note logs.
- **Work breakdown (WBS) proposal** — Your instruction, your operating guide if you have one, the project name and window, groups, milestones, and for each task: name, group, status, start and due dates, estimate, dependencies, assignee and a shortened description. No e-mail addresses or note logs.
- **Next-actions weight suggestion** — The project name, the titles of tasks, RAID items, milestones and changes, the next-actions queue, your current weights and learning counts, a trend summary, and stakeholder names, plus your operating guide for weight suggestions if you have one. No descriptions, notes or e-mail addresses.
- **New project proposal (project wizard)** — Only what you give the wizard: the brief you type, the files you attach (an e-mail with its body and its sender and recipient names and addresses), and the SharePoint files and Confluence pages you pick, plus your operating guide if you have one. No data from existing projects.
- **Speech-to-text dictation** — When you choose a speech-to-text service, the audio you record and that service’s API key go through this app’s own server route to the speech service you configured, not to Anthropic. Without this consent, while AI is switched off, or while that service’s address or key is missing or cannot be read on this device, dictation with that service is unavailable; it never switches to another engine on its own. Only when you choose browser dictation instead, or this deployment has switched speech-to-text off, does it use the browser’s built-in speech recognition, which in some browsers sends audio to the browser maker’s service.

Background (a separate “Allow AI to run in the background” consent; these call the AI on their own, without a click):

- **Scheduled job analysis** — The job’s instruction and, for the project it covers, the same summary as “Analyze next actions with AI”: budget figures, the next-actions queue, open tasks with assignees and due dates, active RAID items with owners, milestones, pending changes and stakeholder names with their title or organisation, plus your operating guide for analyses if you have one. No descriptions, notes or e-mail addresses.
- **Automatic insight recommendations** — The project name, today’s date, the insight’s type, severity and figures, the titles of up to 30 tasks, the names of up to 30 people (active resources and assignees of open tasks), and the item the insight is about: a milestone with its description, a RAID item with its owner and mitigation, or a person’s job title, department and company. For a working-time insight from Timelog the figures are about one person: their name and Timelog user number, on how many days a single entry or a day’s total went over a limit, they logged more than their defined hours, they logged time on a non-working day or on a day they were absent (vacation, sick or training), or time in a closed month was changed, with the worst hours, the limit where there is one and, for a closed month, the net change, and the first and last dates concerned. Also your operating guide for recommendations if you have one. No e-mail addresses and no resource notes.
- **Digest summary, scheduled** — Overall status (RAG), the number of overdue tasks, the numbers of open and high-severity RAID items, and the names and dates of milestones due soon, plus your operating guide for the digest if you have one. No people’s names, notes or e-mail addresses, unless they are in a milestone name.

#### People protection

Protection is on by default in every project, set per project in Settings → AI ("Protect people from the AI") and forced on for every project when the deployment lists `ai-people` in `AIPM_DISABLED_INTEGRATIONS` (enforced in the app only: a modified client could bypass it). Turning it off for a project asks for confirmation and is written to the activity log. The same table row says, for each path, what protection does to it. The limit: names the project does not know, typed into free text or contained in attachments, may still be sent.

- **AI Assistant chat** — The names, email addresses and phone numbers of people the project knows are replaced by placeholders before sending, and the assistant cannot assign, move or rate anyone. Images and scanned documents are refused while protection is on. Names the project does not know, typed into free text or contained in text attachments, may still be sent.
- **Inline AI edit on a row** — The names, email addresses and phone numbers of people the project knows are replaced by placeholders before sending. Names the project does not know, typed into free text or contained in attachments, may still be sent.
- **Steering committee report draft** — The names, email addresses and phone numbers of people the project knows are replaced by placeholders before sending. Names the project does not know, typed into free text or contained in attachments, may still be sent.
- **Digest summary, on request** — The names, email addresses and phone numbers of people the project knows are replaced by placeholders before sending. Names the project does not know, typed into free text or contained in attachments, may still be sent.
- **Forecast import from a spreadsheet** — The names, email addresses and phone numbers of people the project knows are replaced by placeholders before sending. Names the project does not know, typed into free text or contained in attachments, may still be sent.
- **Insight recommendation, on request** — The names, email addresses and phone numbers of people the project knows are replaced by placeholders before sending. Names the project does not know, typed into free text or contained in attachments, may still be sent.
- **Analyze next actions with AI** — The names, email addresses and phone numbers of people the project knows are replaced by placeholders before sending. Names the project does not know, typed into free text or contained in attachments, may still be sent.
- **Allocation plan proposal** — Not available: the feature is hidden while protection is on.
- **RACI suggestion** — Not available: the feature is hidden while protection is on.
- **Duplicate task check** — The names, email addresses and phone numbers of people the project knows are replaced by placeholders before sending. Names the project does not know, typed into free text or contained in attachments, may still be sent.

### Recommendations

- Use dedicated, minimally scoped credentials: an Anthropic API key with a spend limit, a Jira API token with an expiry date, and a Turso token scoped to a single database.
- Do not use this app with production credentials on shared or untrusted machines — anyone with access to the browser profile can read every stored credential.
- Rotate or revoke credentials when a machine changes hands or a key may have been exposed.
