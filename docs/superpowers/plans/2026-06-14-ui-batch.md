# UI Polish & Feature Batch (0.85.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a batch of 18 UI-polish fixes + three small features (snapshot delete, report reorder, dashboard-trends toggle) across many panels.

**Architecture:** Mostly surface-level edits to existing panels, reusing established patterns (`ResetSizeButton`, the budget-bucket drag-reorder, `ADDABLE_REPORTS`, `InfoTooltip`, `print:hidden`). Two small data helpers: a `deleteSnapshots` batch and a settings-backed dashboard-widgets toggle. No Workspace-schema change.

**Tech Stack:** TypeScript, React (Next.js fork), Vitest + RTL, Tailwind, i18n EN+DE (tsc parity).

**Spec:** `docs/superpowers/specs/2026-06-14-ui-batch-design.md`

## Conventions for every task
- One test file: `npx vitest run src/app/<file>.test.tsx`; typecheck `npx tsc --noEmit`; lint `npm run lint`.
- New i18n strings → EN (`i18n.ts`) + DE (`i18n.de.ts`), identical keys (tsc enforces). DE: Edit tool corrupts umlauts AND curls double-quotes — after editing `i18n.de.ts` run `npx vitest run src/app/i18n-encoding.test.ts`, grep your lines, fix via node utf8 write. No ASCII subs.
- Palette: only sanctioned AIPM tokens (esp. tasks 3, 16); the a11y + palette-sweep tests enforce.
- Pure-CSS/layout tasks (no meaningful unit test): assert a structural fact in RTL where cheap (a class/container present), else rely on tsc + the e2e 12-view axe gate; note "visual verification" in the step.
- Commit after each task. No `Co-Authored-By` trailer.

### Task 1: InfoTooltip viewport clamp (planning margin tooltip clips right)

**Files:** Modify `src/app/info-tooltip.tsx`; Test `src/app/info-tooltip.test.tsx`

`InfoTooltip` portals to `document.body` and centers with `left: r.left + r.width/2; transform: translateX(-50%)` — no horizontal clamp, so a right-edge trigger overflows. Add a clamp that keeps the bubble within the viewport.

- [ ] **Step 1: Read** `src/app/info-tooltip.tsx` fully to see the positioning state (the `left`/`top` computed from `getBoundingClientRect()`), and check for an existing test file.
- [ ] **Step 2: Write a failing test** (`info-tooltip.test.tsx`): render a tooltip whose trigger is near the right edge (mock `getBoundingClientRect` to return e.g. `{ left: 1900, width: 20, bottom: 100, right: 1920 }` with `window.innerWidth = 1920`), open it, and assert the bubble's computed `left` plus half its `max-w` does not exceed `innerWidth - margin` (i.e. it shifted left). If the component centers purely via transform with no JS clamp, assert the new clamped inline `left` value.
- [ ] **Step 3: Implement** — after computing the centered `left`, clamp it: keep an 8px margin and the `max-w-[16rem]` (256px) half-width in mind. Replace the centering approach with a clamped absolute left:
```tsx
const MARGIN = 8;
const HALF = 128; // half of max-w 16rem
const centered = r.left + r.width / 2;
const clampedLeft = Math.min(
  Math.max(centered, MARGIN + HALF),
  window.innerWidth - MARGIN - HALF,
);
// use left: clampedLeft with translateX(-50%) (unchanged), so the bubble never crosses the edge
```
(Keep `top: r.bottom + 4`. Guard `window` for SSR — this runs in an effect/open handler already.)
- [ ] **Step 4: Run** the test (PASS) + `npx tsc --noEmit`.
- [ ] **Step 5: Commit** `git commit -m "fix: clamp InfoTooltip to viewport (no right-edge clip)"`
