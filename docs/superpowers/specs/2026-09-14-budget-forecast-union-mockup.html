Finishing the remaining work at current efficiency costs €102,968. At the current burn rate that takes about 76 working days, 7 more than remain before the planned end (around 29 Dec). The current-pace forecast only budgets €93,150 because it assumes the work is done on 18 Dec. Progress so far says it will not be: either the project runs about 7 working days late, or more people are added to hold the date. Either way it costs about €10k more.

My take

The union is the stronger design. It keeps one set of figures for everyone, shows the useful disagreement between pace and progress, and still gives both looks (AIPM burn-down and EVM S-curve) through the chart switch. A method switch mainly hides that disagreement and forces a “whose setting wins” rule on the dashboard and exports.

Decisions either design still needs:

  1. Which forecast is the dashboard headline and RAG source (proposal: current pace, since it always exists).
  2. Agreement threshold for the “forecasts disagree” line (e.g. 10% of BAC).
  3. Names for the three CPIs: price (new), internal cost (“Cost recovery” today), effort (task estimates).
  4. Default chart orientation (proposal: burn-down, matching AIPM), remembered per device.
