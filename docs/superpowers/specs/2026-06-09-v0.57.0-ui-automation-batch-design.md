# v0.57.0 UI + Automation Batch — Design

> Status: **draft for review**. Codename suggestion: "Butler" (Octavia Butler). Target release 0.57.0.

**Goal:** A single batched release covering seven workstreams — view-layout parity & printing, a reminders/notifications redesign, configurable multi-section document export, an AI-Assistant (chat) overhaul, a Settings "Information flows" diagram, a README rewrite, and activity-log completeness.

**Architecture:** Incremental changes inside the existing Next.js 16 / React 19 app. No new runtime dependencies. Reuse existing shared infra: `ReportCard`/`PrintButton`/`useResizable` (view layout), the `NotificationsConfig` + toast/banner system, the OOXML/PDF export builders, the chat hook + Anthropic proxy, the settings-section registry, and `logActivity`. AIPM 9-colour palette only; lint gate `--max-warnings=0`.

**Tech stack:** TypeScript, React 19, Next.js 16 (Turbopack), Vitest 4. localStorage for settings + usage persistence.

**Delivery:** one feature branch (`feat-v0.57-ui-automation-batch`), logical commits per workstream, single GitLab MR → merge. Suggested implementation order: **G → B → A → E → F → D → C** (low-risk first, heaviest export work last).

---

## Resolved decisions (from brainstorming)

1. **Token usage limits:** *Fixed default caps* — ship sensible editable caps; bars fill toward them; 80% of session or week fires a toast; week resets Monday 00:00 local.
2. **Reminder defaults:** *Toasts by default* — pop-up + banner channels default off; reminder sources stay enabled and surface as toasts.
3. **Reminder lead time:** *Global-or-individual* — a "use one global lead time" checkbox (default on) drives every reminder; when off, each reminder gets its own days-ahead input; global disables the per-reminder inputs.
4. **Activity log scope:** *Entities + coarse settings* — add Change-log / Stakeholder / Resource / Role CRUD; one coarse `settings.updated` event (not per keystroke).
5. **Export:** *Invest in generic multi-section rendering* for the four Office/PDF builders.
6. **Batch:** *One MR* for all of A–G.

## Workstream B — Reminders / notifications redesign

### Data shape — `src/app/settings-types.ts`
```ts
export type ChannelConfig = { enabled: boolean; leadDays?: number };

export type NotificationsConfig = {
  useGlobalLeadDays: boolean;        // NEW — default true
  reminderLeadDays: number;          // global lead-days, default 7
  banner: ChannelConfig;             // default { enabled: false }
  toast: ChannelConfig;              // default { enabled: true }
  popup: ChannelConfig;              // default { enabled: false }
  birthday: ChannelConfig;           // default { enabled: true }
  raidReview: ChannelConfig;         // default { enabled: true }
  stakeholderComms: ChannelConfig;   // default { enabled: true }
  jiraTokenError: ChannelConfig;     // NEW — default { enabled: true }, enabled-only (no leadDays)
  raidReviewIntervalDays: number;    // unchanged, default 14
};
```
- **Effective lead-days helper:** `effectiveLeadDays(cfg, channel) = cfg.useGlobalLeadDays ? cfg.reminderLeadDays : (cfg[channel].leadDays ?? cfg.reminderLeadDays)`. Single pure function; unit-tested.
- **Back-compat / migration:** a `sanitizeNotifications(raw)` path must fill `useGlobalLeadDays` (→ `true`) and `jiraTokenError` (→ `{enabled:true}`) for settings persisted before this release, so existing users keep working banners/token alerts.

### Behaviour
- Defaults flip: `popup`/`banner` off, `toast` on. Reminder sources (`birthday`, `raidReview`, `stakeholderComms`, plus due-task alerts) stay enabled → they now surface **as toasts**. Verify each source has a toast path gated by the `toast` channel (due alerts, RAID review, stakeholder comms, birthdays).
- **`jiraTokenError` toggle** (default on) now gates the Jira-token banner render in `task-manager.tsx` (~line 1002), which was previously always-on. The storage-error banner remains always-on (out of scope unless requested).
- RAID review's interval (`raidReviewIntervalDays`) is *not* governed by the global lead-time toggle (different concept); its input stays where it is.

### UI — `src/app/settings-sections/notifications-section.tsx`
- Add the **"Use one global lead time (days ahead)"** checkbox bound to `useGlobalLeadDays`.
- When checked: show the single global `reminderLeadDays` input; the per-reminder day inputs are rendered **disabled**.
- When unchecked: each reminder row (banner, toast, pop-up, birthday, RAID review, stakeholder comms) shows its own days-ahead input bound to `channel.leadDays`.
- Add the `jiraTokenError` enable checkbox.
- New i18n keys: `notifUseGlobalLeadDays`, `notifGlobalLeadDaysHint`, `notifJiraTokenError`, plus per-reminder lead-day labels as needed (EN + DE).

## Workstream C — Configurable multi-section document export

### Config — `src/app/settings-types.ts`
```ts
export const EXPORT_SECTION_KEYS = [
  "tasks","raid","changes","milestones","stakeholders",
  "budgets","resources","roles","absences","shifts","status"
] as const;
export type ExportSectionKey = (typeof EXPORT_SECTION_KEYS)[number];
export type ExportConfig = Record<ExportSectionKey, boolean>;

export const defaultExportConfig: ExportConfig = {
  tasks: true, raid: true,            // default = tasks + RAID only
  changes:false, milestones:false, stakeholders:false, budgets:false,
  resources:false, roles:false, absences:false, shifts:false, status:false,
};
```
- Add `export?: ExportConfig` to `Settings` (optional for back-compat; `sanitize` fills `defaultExportConfig`).

### Generic section model — new `src/app/export-sections.ts`
```ts
export type ExportSection = {
  key: ExportSectionKey;
  title: string;                 // localized
  columns: string[];             // header row
  rows: (string | number)[][];   // body rows, already stringified/sanitized
};
export function buildExportSections(ws: Workspace, cfg: ExportConfig, lang: Lang): ExportSection[];
```
- One place defines, per section key, its localized title + columns + row projection from the workspace. Enabled+non-empty sections only. Pure + unit-tested.

### Format builders consume the generic model
- **PDF** `src/app/export.ts` `exportPdf` → render every `ExportSection` as an HTML table (was tasks+RAID only).
- **DOCX/XLSX/PPTX** `src/app/export-ooxml.ts` `buildDocx`/`buildXlsx`/`buildPptx` → iterate sections: DOCX = heading + table per section; XLSX = one worksheet per section (respect existing frozen header/autofilter/zebra); PPTX = divider slide + item slides per section (respect existing slide caps `PPTX_MAX_SLIDES`/`PPTX_MAX_RAID_SLIDES`, generalized per section; log truncation).
- **CSV/MD** `src/app/storage.ts` `workspaceToCsv`/`workspaceToMarkdown` → filter emitted sections by `ExportConfig`. **Behaviour change:** these currently emit every non-empty section; now they default to tasks+RAID. Markdown `|`-escaping (`mdEscape`) must be preserved for any section with free-text containing `|`.
- `exportWorkspace(...)` in `src/app/export.ts` gains a `cfg: ExportConfig` argument; `src/app/export-menu.tsx` passes `settings.export ?? defaultExportConfig`.

### Settings UI — new `src/app/settings-sections/export-section.tsx`
- Checklist of the 11 section keys (localized labels), bound to `settings.export`.
- Register: add `"export"` to the `RAIL` in `src/app/settings-view.tsx` + import + conditional render + `settingsSectionExport` label key (EN/DE) + per-section label keys.

## Workstream D — AI Assistant (chat) overhaul

### D1 — Rename "Chat" → "AI Assistant"
- `src/app/i18n.ts` + `i18n.de.ts`: `tabChat` → "AI Assistant" / "KI-Assistent". Audit help-text references that say "Chat" and update copy. One key cascades to `nav-config.ts` label + tab.

### D2 — Suggested prompt chips
- **File:** `src/app/chat-panel.tsx` — render clickable chips above the input (or under the greeting). Clicking fills/sends the prompt.
- Prompts: **"Give me an update"** (gather actionable items by criticality & priority, then state recommended next actions), "Show overdue tasks", "What's at risk?", "Draft a status update for stakeholders".
- **Cross-cutting tools:** today `chat-tools.ts` exposes task tools only. Add **read-only** list tools — `list_raid`, `list_changes`, `list_milestones` — to `chat-tools.ts` + dispatcher so "Give me an update" spans RAID/changes/milestones, not just tasks. No mutating tools added here.

### D3 — Token usage panel (AI settings)
- **Capture:** `callClaude()` in `chat-panel.tsx` must return `usage:{input_tokens,output_tokens}`; sum across every turn of the tool-use loop (each turn is a separate API call).
- **Persist:** new `src/app/ai-usage.ts` — daily buckets in localStorage key `lop-app:ai-usage` (`{ "YYYY-MM-DD": { input, output } }`). Pure helpers: `recordUsage`, `sessionTotal` (in-memory since load), `weekToDate(now)` (sum of buckets in current week, Monday start), `nextWeekReset(now)`. Unit-tested with injected `now` (no `Date.now()` in pure code under test).
- **Caps:** add `sessionTokenCap?: number` + `weeklyTokenCap?: number` to `AiConfig` with fixed editable defaults (e.g. session 200_000, weekly 2_000_000). Editable in `ai-section.tsx`.
- **Panel:** in `src/app/settings-sections/ai-section.tsx`, render a **Session** section + two bars — **Current session** and **Current week (all models)** — each `used / cap` with %, plus the week **reset timestamp**. Styled with AIPM palette.
- **80% toast:** when session or week crosses 80% of its cap, fire one `showToast("error", …)`; dedupe so it fires once per threshold-crossing per session (track a "already warned" flag per scope).

### D4 — Stop button
- `AbortController` around the `fetch` in `callClaude`; a `busy`-visible **Stop** button aborts the controller and sets a `cancelled` flag that breaks the tool-use loop between turns. Aborted requests surface a neutral "stopped" state, not an error toast. New i18n `chatStop`.

### D5 — Top-bar AI Assistant button
- Add an **AI Assistant** button to the **left of New Task** in both `src/app/top-bar.tsx` (modern) and `src/app/app-header.tsx` (classic).
- On click → `openPopoutWindow("chat", settings.popout.reuseWindow)` (reuses existing popout infra; chat is already a registered popout tab). New i18n `openAiAssistant`.
